# kabi-lock 設計書

- 日付: 2026-11-24
- 状態: 承認済み（実装前）
- デザイン: https://claude.ai/artifact/Aa9QfmB37CVZbfbhsxBevM （Claude Design のキャンバス）

## 1. 目的

sway 向けの画面ロッカーを Rust で作る。swaylock-effects + 自作ラッパー（`swaylock-touch`）で
試した見た目と認証フローを、1 つのプログラムに収める。

目指す体験:

- Meta+L を押すと、画面が黒からぼかしたスクリーンショットへフェードインする（初期値 1.5 秒）。
- 時計と日付を出し、打鍵ごとに入力バーへ「光の柱」が立ち上がって消える。
- Enter で錠が現れ、成功なら開き、失敗なら横に震える。
- パスワード・YubiKey タッチのどちらでも解除でき、ロック前後の KeePassXC の扱いもまとめて行う。

### 背景（swaylock-effects で分かったこと）

- ext-session-lock では、sway はロック要求を受けた瞬間に全出力を黒で覆う（`sway/lock.c`）。
  ロック画面が届くまでの黒は避けられないので、**黒からフェードする**見せ方にして黒を演出の一部にする。
- swaylock-effects の `--fade-in` は ext-session-lock 下でフレームループが始まらず、約 1 秒止まる
  （fork で修正済み: y1wtt/swaylock-effects）。kabi-lock ではフレームの開始を自分で制御する。
- `--effect-scale` で縮小してからぼかすと画像がずれた。ぼかしは自前で行う。

## 2. スコープ

### v1 に含める

- ext-session-lock によるロック、全出力への背景表示
- wlr-screencopy によるスクリーンショット、ぼかし、黒からのフェードイン
- 主画面への時計・日付・入力バー・錠の表示
- PAM によるパスワード認証
- pam_u2f（YubiKey タッチ）による認証。パスワードと同時に受け付ける
- KeePassXC 連携（ロック前のロック、解除後の解除要求）。設定でオン／オフ
- 設定ファイル（TOML）
- 出力の抜き挿しへの追従
- Arch 用 PKGBUILD

### v1 に含めない

- swayidle 連携やサスペンド前ロックの仕組み（sway 設定から `exec kabi-lock` で呼ぶ想定）
- IME（日本語入力）によるパスワード入力
- sway 以外のコンポジタでの動作保証（ext-session-lock と wlr-screencopy があれば動く可能性はある）
- 外部からのシグナル（SIGUSR1）による解除

## 3. 見た目（デザインの確定事項）

レイアウトは 1920x1080 基準の値で、横は中央寄せ。縦は時計グループ（錠の領域・時計・日付）の上端を
画面の上から 130px に置き、その下に入力バーを置く。主画面の高さが違う場合は高さに比例させる。

| 要素 | 内容 |
|---|---|
| 背景 | ロック直前のスクリーンショットをぼかし、周辺を暗くする（ビネット）。全出力に表示 |
| 時計 | `HH:MM`、Inter 500、104px、白（不透明度 0.94）。字間 -2px、等幅数字 |
| 日付 | 時計の下 14px。初期値 `MM/dd`（例 `11/24`）。26px、白（不透明度 0.74） |
| 錠 | 時計の上、44x52 相当の領域。普段は非表示で、Enter 押下時（YubiKey 成功時も）だけ現れる |
| 入力バー | 時計グループの下 374px。幅 768px、高さ 72px の帯に 16 本のレーン |
| 光の柱 | 幅 32px、レーン間隔 16px（ピッチ 48px）。両端が明るい（不透明度 0.85）、中は 0.38。縦は上が透明・下が不透明。角丸なし |

### アニメーション

- **フェードイン**: 黒 → ぼかし画像（時計なども同じ不透明度で一緒に）。初期値 1500ms。
- **光の柱**: 打鍵ごとに、表示中の柱がないレーンからランダムに 1 本選んで出す。
  下端を基準に縦 0.35 倍から 1.06 倍まで伸びて（全体の 12%）、1.0 倍に戻り（22%）、そのまま消える。初期値 900ms。
  全レーンが表示中なら、一番古い柱のレーンを使う。
- **錠（解除）**: U 字が真上に跳ね上がり（0〜260ms、-11px まで行って -9px に落ち着く）、
  続けて右の長い足を軸に 180° 回る（260〜800ms、ease-in-out）。
  U 字は太さ一定の丸棒として扱い、短い足の x を `42 - 20·cos(θ)` で動かし、上の半円も合わせて変形する
  （左右反転のスケールは使わない。線が細くなって紙のように見えるため）。
  その後、ぼかしがくっきりしたスクリーンショットへ戻り、時計などが消え（約 700ms）、ロックを外す。
- **錠（失敗）**: 左右に震える（450ms、振幅 10px から減衰）。約 1.2 秒後に錠が消える。
- **錠の形**: 本体は角丸（rx 6）の塗りつぶし、鍵穴なし。U 字の上は半円。右足が長く本体の中まで入る。

## 4. 構成

### 使うクレート

| 役割 | クレート |
|---|---|
| Wayland、イベントループ、キー入力 | `smithay-client-toolkit`, `calloop` |
| スクリーンショット | `wayland-protocols-wlr`（wlr-screencopy） |
| GPU | `khronos-egl`, `wayland-egl`, `glow`（OpenGL ES 3） |
| 文字と図形 | `egui`, `egui_glow`（0.37 系） |
| パスワード / YubiKey | `pam-client` |
| KeePassXC | `zbus` |
| 設定 | `serde`, `toml` |
| 日付 | `chrono`（ロケール対応） |
| フォーカス中の出力 | `swayipc` |
| パスワードのメモリ | `zeroize` |
| ログ | `log`, `env_logger` |

### 描画の分担

- 自前の GL シェーダー: 背景（ぼかし、フェード、ビネット、解除時のぼかし解除）
- egui（`egui_glow`）: 背景の上に重ねる時計・日付・光の柱・錠
- キー入力は SCTK で直接受け取り、egui には渡さない

### モジュール

| モジュール | 責務 | 依存 |
|---|---|---|
| `config` | 設定の読み込みと初期値、主画面の選択（出力名・説明文で照合） | なし |
| `anim` | 経過時間からフェード不透明度・柱の状態・錠の形・震えの量を返す純粋関数 | なし |
| `lanes` | 光の柱のレーン割り当て | なし |
| `state` | ロック中の状態遷移（イベント → 次の状態）。純粋な関数 | なし |
| `password` | `zeroize` 付きのパスワードバッファ（追加・削除・全消去） | `zeroize` |
| `wl/` | 出力一覧、スクリーンショット、session lock、キー入力 | SCTK |
| `render/egl` | EGL ディスプレイ・コンテキスト、出力ごとの EGL サーフェス | `khronos-egl` |
| `render/background` | スクリーンショットのテクスチャ化、縮小ぼかし、フェード描画 | `glow` |
| `render/overlay` | egui の準備（フォント・アトラス）と毎フレームの描画 | `egui_glow` |
| `auth/password` | PAM でのパスワード確認（スレッド） | `pam-client` |
| `auth/u2f` | pam_u2f でのタッチ待ち（スレッド、ループ） | `pam-client` |
| `auth/keepassxc` | ロック前の DB ロック、解除後の解除要求 | `zbus` |
| `main` | 起動順の制御、イベントループ、各モジュールの結線 | すべて |

認証スレッドと描画のイベントループはチャンネル（`calloop::channel`）でやりとりする。描画側が認証でブロックされることはない。

## 5. 起動からロックまで

計測（AMD Radeon 860M）: EGL 初期化 21〜24ms、egui_glow 準備（シェーダーのコンパイル）3〜8ms、
初回フレーム（CPU 1.6ms + アトラス転送 1〜1.8ms + 描画 2.5ms）。2 回目以降は 0.1〜0.6ms。
重いのは初期化なので、ロック要求の前に済ませる。

1. 設定を読み、出力一覧を取る。主画面が設定で決まらないときのために、
   sway IPC（`SWAYSOCK`）の `get_outputs` で `focused` の出力を記録する。
   IPC が使えなければ、出力一覧の最初の出力を使う。
2. 次を並行して進める。
   - 全出力のスクリーンショットを撮る（wlr-screencopy）
   - EGL 初期化、シェーダーのコンパイル、フォント読み込み、egui の準備、アトラスの事前転送
3. スクリーンショットを GPU に送り、縮小してぼかしたテクスチャを作る（元画像も解除アニメーション用に残す）。
4. `keepassxc.lock_before` なら KeePassXC に全 DB のロックを依頼する（完了は待たず、確認は裏で続ける）。
5. ext-session-lock でロックを要求し、返事を待たずに全出力のロックサーフェスを作る。
6. configure が届いた出力から黒を 1 枚出し、フェードを始める。以後はフレームコールバックで描く。

## 6. ロック中の状態と認証

### 状態

| 状態 | 表示 | 遷移 |
|---|---|---|
| 入力待ち | 時計・日付・入力バー。錠は非表示 | Enter（バッファが空でない）→ 確認中 / U2F 成功 → 解除中 |
| 確認中 | 錠が現れる。キー入力は無視 | PAM 成功 → 解除中 / 失敗 → 失敗 |
| 失敗 | 錠が震える。バッファは空にする | 約 1.2 秒で入力待ち。震えている間もキー入力は受け付ける |
| 解除中 | 錠が開く → ぼかしが晴れ、重ね物が消える | アニメーション終了でロックを外して終了処理へ |

U2F の成功は「入力待ち」「失敗」のどちらからでも解除中へ進む。「確認中」に U2F が成功した場合も解除中へ進み、
パスワードの結果は捨てる。

### パスワード

- キー入力を xkbcommon で文字に変換し、パスワードバッファに追加する。打鍵ごとに光の柱を 1 本出す。
- Backspace は 1 文字消して柱を出す。Esc と Ctrl+U は全消去（柱は出さない）。
- Enter でバッファの内容を認証スレッドへ渡し、PAM（`auth.pam_service`、初期値 `kabi-lock`）で確認する。
  渡した後、メインスレッド側のバッファは消去する。

### YubiKey（`auth.u2f.enabled`）

- ロック中は別スレッドで PAM（`auth.u2f.pam_service`、初期値 `kabi-lock-u2f`）の `pam_authenticate` を繰り返す。
- 会話関数はパスワード等の入力要求に答えず失敗にする（既存の `u2f-touch-check` と同じ方針）。
- 成功したらメインへ通知。失敗したら 1 秒あけて再試行する（キー未接続時の空回り防止）。
- 解除が決まったらスレッドは放置し、プロセス終了で片付ける（PAM 呼び出しは中断できないため）。

### KeePassXC

- `keepassxc.lock_before`: `org.keepassxc.KeePassXC.MainWindow.lockAllDatabases` を呼ぶ。
  未起動なら何もしない。その後 Secret Service の各コレクションの `Locked` を最大 2 秒確認し、
  ロックされないものが残れば通知（`org.freedesktop.Notifications`）を出す。ロックの進行は止めない。
- `keepassxc.unlock_after`: ロックを外した後、Secret Service でロック中のコレクションがあれば
  `Unlock` を呼び、返ったプロンプトの `Prompt` を呼ぶ（KeePassXC の解除ダイアログが出る）。

### PAM 設定ファイル

- `/etc/pam.d/kabi-lock`（`auth include login`）はパッケージで入れる。
- U2F 用はユーザーごとに `authfile` が違うので入れない。`contrib/pam.d/kabi-lock-u2f` に例を置く。
  既存の `u2f-touch` などを `auth.u2f.pam_service` で指定してもよい。

## 7. 設定ファイル

場所: `$XDG_CONFIG_HOME/kabi-lock/config.toml`（なければ `~/.config/kabi-lock/config.toml`）。
すべて省略可能。未知のキーは警告して無視する。

```toml
[display]
# 時計・日付・入力バー・錠を出す画面。上から順に照合し、最初に一致したものを使う。
# 出力名（"DP-10"）またはモニターの説明文（wl_output の description）と完全一致で比べる。
# 一致しなければ、ロック前にフォーカスしていた出力（sway IPC）、それも分からなければ最初の出力。
primary = []

[appearance]
fade_in_ms = 1500
blur = 7                 # ぼかしの強さ（縮小後のガウスの σ 相当）
date_format = "%m/%d"    # chrono の strftime 形式。曜日などは LC_TIME のロケールに従う

[input]
pillar_fade_ms = 900
pillar_width = 32
band_width = 768         # レーン数は (band_width + 16) / (pillar_width + 16) の切り捨て

[auth]
pam_service = "kabi-lock"

[auth.u2f]
enabled = true
pam_service = "kabi-lock-u2f"

[keepassxc]
lock_before = true
unlock_after = true
```

### フォント

- Inter（OFL）をバイナリに埋め込み、時計・日付に使う。ライセンス文を同梱する。
- `date_format` の結果に Inter にない文字（日本語など）が含まれる場合に備え、
  fontconfig で `sans-serif:lang=<LC_TIME の言語>` を引き、egui のフォールバックとして登録する。
  見つからなければ登録しない（その文字は表示されないが、ロックは続ける）。

## 8. エラー時の動き

方針: **何があってもロックは掛ける**。ロックできないときだけ終了する。

| 状況 | 動き |
|---|---|
| 設定ファイルが読めない・不正 | 警告をログに出し、初期値で続ける |
| 一部の出力のスクリーンショットに失敗 | その出力の背景は黒 |
| EGL 初期化に失敗 | `wl_shm` の黒いバッファでロックする。重ね物は出ないが、パスワード・YubiKey で解除できる |
| ext-session-lock が使えない / 拒否された（`finished`） | エラーを出して終了コード 1 |
| ロック中に出力が増えた | ロックサーフェスを作る（背景は黒） |
| ロック中に出力が減った | その出力のサーフェスを片付ける。主画面だった場合は残りから選び直す |
| PAM がエラーを返した | 失敗として扱う |
| kabi-lock が異常終了した | プロトコル上、sway はロックしたまま（赤）。再起動すれば解除できる |

パスワードはログに出さない。パスワードを含むメモリは使用後に `zeroize` で消す。

## 9. テスト

### 単体テスト（`cargo test`）

- `anim`: フェード不透明度の両端と単調性、柱の伸びと消え方、錠の形（0ms で閉じた形、800ms 以降で反転した形、
  全期間で線の太さが変わらないこと＝形状がパスとして妥当なこと）、震えの減衰
- `lanes`: 表示中の柱と重ならない、全レーン使用中は一番古いレーンを使う、柱の幅を変えるとレーン数が変わる
- `config`: 省略時の初期値、未知キー、主画面の照合（出力名・説明文・一致なし）
- `state`: 各状態でのイベントと遷移（U2F 成功の割り込み、確認中のキー入力無視など）
- `password`: 追加、Backspace、全消去、空での Enter

### 手動確認

- 入れ子の sway（`WLR_BACKENDS=wayland sway`）の中で起動し、本物のセッションをロックせずに確かめる。
- 実機では一度だけ、3 枚の出力（DP-10 / DP-8 / eDP-1）で見た目・フェード・解除を確認する。
